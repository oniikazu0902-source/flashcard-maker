## v1 の問題の確認

| v1 の問題 | v2 の結果 |
|---|---|
| R1 極値の値を検算できない | 解消。3-1〜3-3 は極大・極小の位置と値まで OK |
| R2 問題文と検算の式が別々 | 解消。問題の式はスクリプトの LaTeX をそのまま使った |
| R3 答えを手で書き直している | 解消。答えもスクリプトの LaTeX を使った |
| R4 極値の検算ファイルが長い | 解消。1問1件になり、14件 → 10件（1問追加込み） |
| R5 ファイルの置き場所 | 解消（手順に明記） |
| R6 SymPy がない環境 | 手順に追加（今回は SymPy がある環境なので発生せず） |

## 新しく見つかった問題

| # | 問題 | 具体例 | 原因 |
|---|---|---|---|
| S1 | 正しい答えが NG になる | 3-4 $f(x) = x^4 - 4x^3$：答え「$x = 3$ で極小値 $-27$（$x = 0$ は極値でない）」は正しいが NG。手順どおり出力から外したため、良い問題が消えた | スクリプトは $f''$ の符号で判定しており、$f''(0) = 0$ だと判定できない。受験で使う増減表（$f'$ の符号の変化）で判定していない |
| S2 | 問題文がおかしくなる | 「$f(x) = x^{3} - 12 x$ を求めよ。」— 極値の問題なのに「の極値を」が抜けた | 出力形式の「を求めよ。」が全部の型で共通。型ごとの問題文がない |
| S3 | 数式の中に日本語が入る | 「$x = -2 で極大値 16、…$」— 日本語まで数式として表示され、字間がおかしくなる | スクリプトの答えを丸ごと `$…$` で囲むルールにしたため |
| S4 | LaTeX が冗長で読みにくい | `\sin{\left(2 x \right)}`（普通は `\sin 2x`）、`\frac{1}{4} + \frac{e^{2}}{4}`（普通は `\frac{e^2 + 1}{4}`） | SymPy の標準の LaTeX 出力をそのまま使っているため。文字数も多く、トークンも増える |

## ruidai-v3 での対応方針

- 極値の判定を増減表と同じ方法（$f'$ の符号の変化）に変え、「極値でない点」も表示する（S1）
- スクリプトが型ごとの問題文を、`$` で囲んだ形で出力する。日本語は数式の外に出す（S2・S3）
- 関数のかっこを省き、答えは短い形（通分など）を選んで表示する（S4）
