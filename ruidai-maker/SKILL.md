# ruidai-maker

数学の問題をもとに、**類題**を作るか、**解答例**を作る。答えは必ずスクリプトで検算する。
「解答例」「解いて」と頼まれたら、下の「解答例モード」に従う。

## 入力

- 元問題と、その解答（解き方がわかるもの）。講義ノート全体は不要。

## 類題の作り方（変え方）

ユーザーの指定がなければ「数値替え」にする。

- **数値替え**：係数・定数・区間だけを変える。
- **条件替え**：区間や条件を変える。
- **設定替え**：同じ解法を、別の関数や場面で使う。

## 検算できる型

| 分野 | type |
|---|---|
| 極限・定積分・導関数・方程式 | `limit` `integral` `derivative` `solve` |
| 極値・閉区間の最大最小 | `extrema` `maxmin` |
| 2変数関数の極値 | `extrema2` |
| マクローリン展開（一般項） | `series` |
| 偏微分・重積分 | `partial` `double_integral` |
| 線形代数（行列式・逆行列・固有値・固有ベクトル・階数、$P^{-1}AP$ や $A^n$ などの行列の式） | `matrix` |
| 連立1次方程式（解なし・無数・ただ1つになる定数、一般解） | `linsys` |
| 常微分方程式（一般解・初期値問題） | `ode` |
| 確率（箱から球を取り出す、条件付き確率） | `prob` |
| 「〜を示せ」の等式（結論だけを確かめる） | `identity` |

検算用ファイルの書き方は `references/types.md` にある。**使う型の節だけを読む**（全部は読まない）。
どの型にも当てはまらない問題（等式でない証明、図形の問題など）は、検算せずに「検算：対象外」と書く。

## 手順

1. **検算の準備を確認する。** `python -c "import sympy"` が成功するか確かめる。
   失敗したら、ユーザーに `python -m pip install --user sympy` を案内する。
   入れられない場合は類題を作ってよいが、すべての類題に「検算：未実施」と書き、答えが誤っている可能性を伝える。
2. 元問題の解法の要点を1行でまとめ、使う型を決める。
3. 指定された数だけ類題を作る（指定がなければ3問）。
   数値替えだけを並べると答えの形がそろい、パターンで解けてしまうことがある。
   3問以上作るときは、条件替え・設定替えを少なくとも1問混ぜる（例：右辺を変えて、「解なし」になる値と「解が無数」になる値を入れ替える）。
4. 検算用ファイル `problems.json` を作業用の一時フォルダに保存する（ユーザーのファイルと混ぜない）。
5. このスキルのフォルダにある `scripts/verify.py` で検算する：
   `python <このスキルのフォルダ>/scripts/verify.py <一時フォルダ>/problems.json`
6. NG・ERROR の問題は直して、もう一度検算する。
7. 出力する。**問題文と答えは、スクリプトが表示したものをそのまま使う**（`$` で囲み直したり、式を書き直したりしない）。
   条件替えなどで前置き（「$a > 0$ とする。」など）が必要なときは、問題文の前に書き足してよい。

## スクリプトの表示

```
[OK] 5
  問題: $f(x) = x^{3} - 3 x$ の極値を求めよ。
  答え: $x = -1$ で極大値 $2$、$x = 1$ で極小値 $-2$
```

## 出力形式

```
### 類題1（数値替え）
**問題**：<スクリプトの「問題」>
**答え**：<スクリプトの「答え」>
**要点**：…（3行以内）
元問題：例題1 ／ 検算：OK
```

- 解説は要点3行まで。詳しい解説はユーザーに頼まれたときだけ書く。
- 類題は教材にない自作の問題なので、必ず「元問題」を書いて区別する。

## 解答例モード（過去問などの解答例を作る）

問題はすでにあるので、類題は作らない。答案として採点者に伝わる解答を書き、答えを検算する。

1. 検算の準備を確認する（上の手順1と同じ）。
2. **問題を1大問ずつ読む。** 一度に全部の大問を解かない（途中で誤りが混ざりやすく、トークンも増える）。
3. 小問ごとに、問題文にある**解き方の指定**を書き出す。
   例：「数学的帰納法を用いて」「部分積分を用いて」「前問の結果を用いて」「〜を用いて」。
   指定がある小問は、答えが合っていても**指定どおりの方法で**解く。別の方法で値だけ求めた解答は不可。
4. 解答を書く。
   - 途中式を省かない。「対称性より」「明らか」のように、根拠を書かずに飛ばさない。計算で示せるところは計算で示す。
   - 前の小問の結果を使うときは「(2) より」のように書く。
5. 検算する。小問ごとに、使える型で `problems.json` を作り、`scripts/verify.py` を実行する。
   - 「求めよ」の小問：答えを検算する。
   - 「〜が成り立つことを示せ」の等式：`identity` 型、または行列なら `matrix` の `expr` で、**結論の等式**を確かめる。
   - 数学的帰納法で示す式（$B^n = \ldots$ など）も、式そのものは `matrix` の `expr` などで確かめられる。
   - NG になったら解答を直して、もう一度検算する。
   - スクリプトが「注意」を表示したら（数値で照合した、最初の10項だけ照合した、など）、その小問は `検算：OK（注意の内容）` と書く。
   - 「判定できない（要確認）」と表示されたら、`検算：対象外（要確認）` とし、理由を1行で書く。
6. 出力する。小問ごとに、検算の状態を次の3つのどれかで書く。
   - `検算：OK` … 答えをスクリプトで確かめた
   - `検算：結論のみ` … 示すべき等式は確かめたが、証明の過程は確かめていない
   - `検算：対象外（要確認）` … 確かめられなかった。人が確認する必要がある

```
## 問題1
(1) <解答。途中式を含める>
　　検算：OK
(2) <解答>
　　検算：結論のみ
```

- 問題文は書き写さない（トークンの節約。著作権のある過去問を必要以上に複製しないため）。「問題1 (1)」のように番号で示す。
- 大学の公式の解答例があるときは、作った解答例と比べ、違う点（答え・解き方・書き方）を最後に報告する。
- 過去問の解答例は問題の内容を含む。公開する場所（GitHub など）には保存しない。
