## ruidai-v2 — 極値の検算に対応し、式を1回だけ書く作りに変更

v1 で元問題3問から類題9問を作り、検算した（詳細：`examples/outputs/v1/review.md`）。
答えはすべて正しく、わざと入れた誤答も NG と判定されたが、次の問題が見つかった。

### 何が問題だったか → どう直したか

| 問題 | 直し方 |
|---|---|
| 極値問題は $f'$ と $f' = 0$ の解しか検算できず、極大値・極小値そのものは未確認だった | スクリプトに `extrema` 型を追加。$f''$ の符号で極大・極小を判定し、値まで照合する |
| 極値1問につき検算ファイルを2件書く必要があり、長かった | `extrema` 型で1件にまとまった |
| 問題文（LaTeX）と検算の式（Python）を別々に書いていて、食い違っても気づけない | スクリプトが問題の式を LaTeX で表示し、出力ではそれをそのまま使う。式を書くのは検算ファイルの1回だけ |
| スクリプトの答え `1/4 + exp(2)/4` を手で LaTeX に直していて、写し間違いが起きうる | スクリプトが答えも LaTeX で表示する |
| `problems.json` の保存場所とスクリプトの実行場所があいまい | 一時フォルダに保存し、スキルのフォルダの `scripts/verify.py` を指定して実行すると明記 |
| SymPy がない環境での動きが決まっていない | 最初に確認し、入れられなければ「検算：未実施」と書いて伝える |

### トークン節約の効果
類題の式を、問題文（LaTeX）と検算ファイル（Python）に2回書いていたのが1回になった。
AIが LaTeX を組み立てる分の出力も減った。

## ruidai-v1 — 最初の版

### 作ったもの
- `SKILL.md`：類題の変え方（数値替え・条件替え・設定替え）、手順、検算用ファイルの書き方、出力形式
- `scripts/verify.py`：SymPy で答えを計算し、想定した答えと照合するスクリプト（極限・定積分・導関数・方程式に対応）
- `examples/sample-problems.md`：動作確認用の元問題3問（極限・定積分・極値）

### スクリプトを入れた理由
類題でいちばん危ないのは、AIが答えを間違えることです。AIが長い計算を自力で検算するとトークンを多く使い、それでも間違えることがあります。
計算は SymPy に任せたほうが、安くて確実です。

### トークン節約のための方針
- 入力は元問題と解答だけにする（講義ノート全体は渡さない）
- 解説は要点3行まで
- 検算はAIが自分で計算せず、スクリプトに任せる
