# CHANGELOG（ruidai-maker）

類題作成スキルの変更履歴です。タグは flashcard-maker と区別するため `ruidai-v1`、`ruidai-v2`… とします。
動作確認の結果は `examples/outputs/` にあります。

## ruidai-v5 — 問題文のあいまいさをなくし、答えを教科書の書き方に近づけた

v4 で新しい4分野の類題13問を検算した（詳細：`examples/outputs/v4/review.md`）。
答えはすべて正しかったが、表示に次の問題が見つかった。

### 何が問題だったか → どう直したか

| 問題 | 直し方 |
|---|---|
| 重積分の問題文 $\int_0^1\int_0^x 2x + y \, dy \, dx$ で、$(2x + y)$ を積分するのか分からない | 積分・極限の中身が足し算なら、かっこで囲む |
| 答えが $- e^{2x} + 2e^{x}$ のようにマイナスから始まる | 足し算はプラスの項から始める（$2e^x - e^{2x}$） |
| 固有値が $6,\ 1$ のように不自然な順に並ぶ | 固有値・方程式の解は小さい順に並べる |

## ruidai-v4 — 偏微分・重積分・線形代数・微分方程式の検算に対応

v3 の残課題（`examples/outputs/v3/review.md` の T1〜T4）を直した。

### 何が問題だったか → どう直したか

| 問題 | 直し方 |
|---|---|
| 編入数学の主要分野（偏微分・重積分・線形代数・微分方程式）を検算できない | 型を追加：`partial`、`double_integral`、`matrix`（行列式・逆行列・固有値・階数）、`ode`（一般解・初期値問題） |
| 閉区間の最大・最小を検算できない | `maxmin` 型を追加（端点と $f'(x) = 0$ の点の値を比べる） |
| $\sin x$ のような周期関数の極値が ERROR になる | `extrema` に範囲（`interval`）を指定できるようにした |
| 導関数の答えが $x(x \cos x + 2 \sin x)$ とくくった形になる | 導関数・偏導関数・微分方程式の解は、展開した形を優先して表示 |

### 一般解の検算の工夫
一般解は $C_1 e^{2x} + C_2 e^{3x}$ と $C_2 e^{2x} + C_1 e^{3x}$ のように、定数の付け方が違っても正しい。
そこで「答えが方程式を満たすか」と「任意定数の数が階数と同じか」で判定する。

### トークン節約のための変更
型が増えて SKILL.md が長くなるため、型ごとの書き方を `references/types.md` に分けた。
SKILL.md には型の一覧だけを書き、使う型の節だけを読むように指示した。

### 作っている途中で見つけて直したこと
- PowerShell で保存した `problems.json` を読み込めなかった。Windows のメモ帳や PowerShell はファイルの先頭に BOM を付けるため。BOM 付きでも読めるようにした
- 微分方程式が `y + y''` の順で表示された → 階数の高い項から並べるようにした
- `$…$の極値` のように、数式と「の」の間に空白がなかった → 修正

## ruidai-v3 — 増減表と同じ判定にし、問題文・答えをそのまま使える形で出力

v2 で類題10問（v1 と同じ9問＋設定替え1問）を検算した（詳細：`examples/outputs/v2/review.md`）。

### 何が問題だったか → どう直したか

| 問題 | 直し方 |
|---|---|
| $x^4 - 4x^3$ の極値で、正しい答えが NG になり、良い問題が出力から消えた（$f''(0) = 0$ で判定できない） | 判定を増減表と同じ方法（$f'$ の符号の変化）に変更。「$x = 0$ は極値ではない」も表示する |
| 「$f(x) = x^3 - 12x$ を求めよ。」と、極値の問題なのに問題文がおかしくなった | スクリプトが型ごとの問題文（「の極値を求めよ」「を解け」など）を作る |
| 「$x = -2 で極大値 16$」と、日本語まで数式に入っていた | スクリプトが `$` を付けた形で出力し、日本語は数式の外に出す。出力では囲み直さない |
| `\sin{\left(2 x \right)}`、`\frac{1}{4} + \frac{e^{2}}{4}` と LaTeX が冗長 | 関数のかっこを省略（`\sin {2 x}`）し、答えは通分・因数分解した形のうち最も短いものを選ぶ |

## ruidai-v2 — 極値の検算に対応し、式を1回だけ書く作りに変更

v1 で元問題3問から類題9問を作り、検算した（詳細：`examples/outputs/v1/review.md`）。
答えはすべて正しく、わざと入れた誤答も NG と判定されたが、次の問題が見つかった。

### 何が問題だったか → どう直したか

| 問題 | 直し方 |
|---|---|
| 極値問題は $f'$ と $f' = 0$ の解しか検算できず、極大値・極小値そのものは未確認だった | スクリプトに `extrema` 型を追加。$f''$ の符号で極大・極小を判定し、値まで照合する |
| 極値1問につき検算ファイルを2件書く必要があり、長かった | `extrema` 型で1件にまとまった |
| 問題文（LaTeX）と検算の式（Python）を別々に書いていて、食い違っても気づけない | スクリプトが問題の式を LaTeX で表示し、出力ではそれをそのまま使う。式を書くのは検算ファイルの1回だけ |
| スクリプトの答え `1/4 + exp(2)/4` を手で LaTeX に直していて、写し間違いが起きうる | スクリプトが答えも LaTeX で表示する |
| `problems.json` の保存場所とスクリプトの実行場所があいまい | 一時フォルダに保存し、スキルのフォルダの `scripts/verify.py` を指定して実行すると明記 |
| SymPy がない環境での動きが決まっていない | 最初に確認し、入れられなければ「検算：未実施」と書いて伝える |

### トークン節約の効果
類題の式を、問題文（LaTeX）と検算ファイル（Python）に2回書いていたのが1回になった。
AIが LaTeX を組み立てる分の出力も減った。

## ruidai-v1 — 最初の版

### 作ったもの
- `SKILL.md`：類題の変え方（数値替え・条件替え・設定替え）、手順、検算用ファイルの書き方、出力形式
- `scripts/verify.py`：SymPy で答えを計算し、想定した答えと照合するスクリプト（極限・定積分・導関数・方程式に対応）
- `examples/sample-problems.md`：動作確認用の元問題3問（極限・定積分・極値）

### スクリプトを入れた理由
類題でいちばん危ないのは、AIが答えを間違えることです。AIが長い計算を自力で検算するとトークンを多く使い、それでも間違えることがあります。
計算は SymPy に任せたほうが、安くて確実です。

### トークン節約のための方針
- 入力は元問題と解答だけにする（講義ノート全体は渡さない）
- 解説は要点3行まで
- 検算はAIが自分で計算せず、スクリプトに任せる
